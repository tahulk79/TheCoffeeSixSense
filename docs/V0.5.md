# v0.5 — Your First Shift

## Intent and scope

The owner requested v0.5 before a fresh engagement review. Give the existing
three-stage lab a short, finite, character-led first session instead of adding
more systems. Mai, an original code-drawn café regular, asks for three observable
goals. Existing free practice, v0.4 A/B/radar/history, live counter, actual-brew
collection, evidence caveats, local OCR/photos and opt-in music stay available.
Main inspected at `4a2147297252026b9e09a6522c1c66d32da2ee1b`; GitHub Pages URL and
manual workflow unchanged: <https://tahulk79.github.io/TheCoffeeSixSense/>.

## Playable first session

- **Pause & observe:** optional “Play your first shift” starts a preset Brazil
  game lot with 12 g / 180 ml water directly at the station. Save A with at least
  one deliberate mid-stage release. Automatic stage boundaries, focus loss,
  cancellation and taps before water moves do not count. Failed attempts remain
  normal saved memories; Mai explains the unmet goal without claiming bad taste.
- **Try:** use saved A as the baseline for B. Keep the recipe fixed except one
  grind step. A suggested step is prefilled and can be reviewed; starts with a
  larger change are rejected. This is a recipe-reading game exercise, not a
  demonstration that the model predicts the real sensory effect of grinding.
- **Notice:** read A/B settings, choose the changed field. A wrong choice gives a
  hint; correct observation must be saved for this exact B. Only then show the
  “Pause to discover” keepsake and a three-step recap. This is not certification,
  a measured coffee quality score, or proof that a player has mastered brewing.

Cup saves bring the next goal into view. Stage transitions still keep station and
controls mounted and stationary; independent water/drop drawdown and final-drop
wait remain. A live pause count separates handling feedback from recipe score.
The 600 ml server display and liquid clipping are retained. VI/EN throughout.

## Completion and feedback

The recap opens the saved pair or the existing actual-brew collector. “New shift”
explicitly resets the active shift, answer and survey with a new ID, while keeping
all cup memories. The keepsake is for the active shift, not an archive of badges.
The optional local survey stores 1–5 enjoyment, return intention and a short
comment. No telemetry or automatic upload. Intention to return is **not** observed
retention. A shift export includes its session, all associated attempts (including
failed attempts), current proof IDs, pending-progress flag and unsaved feedback.

## Data and failure behavior

- Keep `c6s.first-pour.v03` and envelope version 1. New cups may carry optional
  `practice: {version:1, pauses}` and `shift: {id, role: 'a'|'b'}`. Legacy entries
  remain readable without migration; malformed metadata is protected by the
  existing recovery rules. Score model `first-pour-0.3.1` is unchanged.
- New `c6s.first-shift.v1` stores active session ID, answer tied to B ID and optional
  experience feedback. Goals derive from **saved** cup records for that session;
  unsaved drafts never award progress, and no second progress write is needed for
  a saved cup. Correct-answer write failure cannot show a saved completion.
- Missing/deleted A or B removes its proof and offers recovery through play; no
  cascade deletion of other memories. A new B cannot reuse an old B's answer.
- Corrupt shift data is not overwritten. Export the original; free practice still
  works. Quota errors keep pending progress exportable/retryable and do not wipe
  saved memories. In-progress pours remain in memory and restart after reload;
  saved chapters/answers/feedback resume.
- No accounts, backend, payment, tracking, remote AI, new graphics library,
  flavor coefficients or real-brew/scientific export changes.

## Verification

- `npm test`: 73 checks, including exact saved-proof requirements, wrong/old B
  answers, automatic/zero pause and wrong-volume failures, one-step constraints,
  deletion/new-shift behavior, legacy metadata compatibility and corrupt stores.
- `npm run build:pages`, `npm run build`: successful standalone and Vite artifacts.
- `smoke-first-shift.mjs`: 320/390/820/1440 px; no-pause retry, deliberate keyboard
  release versus forced stop, saved A/reload, one-step B rejection/acceptance,
  language preservation, wrong/correct persisted quiz, quota retry before recap,
  feedback preservation/export, actual-brew link, fresh shift and proof deletion.
  Also tests quota at first start and corrupt shift data without blocking free
  brewing. Real-clock pointer release/cancellation checked separately.
- Existing layout matrix measures stable controls/scroll/node identity in VI/EN.
  Independent animation/release/final-wait/reduced-motion, v0.4 discovery,
  complete memory lifecycle, old counter, actual-brew provenance/recovery and
  music lifecycle checks remain covered.

Screenshots in `docs/review/v0.5/` use synthetic test data. Browser tests use
Chromium; actual Safari/iPad M5 hardware and human engagement remain unverified.
“About three minutes” is a session estimate, not a measured usability result.

## Next: engagement review, not another feature release

Use one fresh browser profile and one returning profile. Observe a whole shift
without coaching, then free play. Record where the person hesitates or scrolls,
when the water/drop animation feels satisfying, whether failure feedback makes
sense, whether B feels worth trying and whether the recap creates another goal.
Ask the player to describe one thing learned; distinguish reading a game recipe
from improving a real brew. Ask about willingness to return, then observe a
later voluntary visit rather than substituting the survey for retention.

Known design risks: the pour cadence remains largely fixed; B reuses the same
basic mechanics; the quiz is deliberately easy onboarding; a finite first shift
is not long-term replay content. This release prepares an honest playtest and
must not be described as proving that the game is engaging or educationally
validated. Do not add world management, monetization or more content before
reviewing this session.
