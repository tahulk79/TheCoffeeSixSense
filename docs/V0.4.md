# v0.4 — One Change, One Discovery

## Scope

The supplied GDD had no separately fixed v0.4 scope. This release implements its
MVP continuation: purposeful A/B replay and user-entered sensory maps. It extends
the existing First Pour lab; it does not introduce another separate game mode.
The owner requested continuing to v0.4 after approving the existing Pages release
workflow. No backend, accounts, telemetry, ML, management, economy or paid content.

Baseline main inspected: `60ea4ba3d3e3c239f3a361b978cf28c61e4a4a37`.
Production URL and manual Pages workflow remain unchanged:
<https://tahulk79.github.io/TheCoffeeSixSense/>.

## Player flow

1. Brew and save a first cup, or reopen any existing v0.3 Coffee Memory.
2. **Brew this recipe** restores its recipe as an independent free brew.
3. **Try one change** uses the saved cup as A. Pick grind, temperature, ratio or
   planned recipe time. Only the selected input is shown; fixed values are available in a compact
   disclosure. Other recipe fields and bean stay fixed; switching the
   selected variable resets to A so earlier edits cannot accidentally carry over.
4. Change the selected value. Unchanged/multiple-variable input is rejected.
   Complete the same tactile three stages, with stable controls and last drops.
5. B shows the changed field and the two **game recipe** scores, without inferring
   actual taste quality. Add optional sensory intensities, enjoyment and notes.
6. Save B, then **View saved A/B pair** opens the linked numerical comparison
   and sensory maps. Notes and next-change intentions stay with each cup.

Returning players get a direct last-saved-cup action. History includes literal,
case/accent-insensitive search over bean name/process, notes and next change.
Comparison is collapsed until requested, keeping saved-recipe actions reachable.
Search filters the visible history only; export always includes all saved records.

## Sensory maps and honest feedback

Original lightweight SVG radar shows six **user-entered** intensities, 1–5.
Missing ratings stay missing: no zero substitution, no closed/fill polygon until
all six values exist; partial maps only join adjacent rated axes. Visible numeric
values accompany the chart, and A/B use distinct line styles as well as colors.
A larger shape is not a better coffee or an enjoyment score. Enjoyment stays
separate. Mixed reflection vs self-reported-real-tasting contexts are explicitly
flagged. None of these inputs becomes measured or calibrated scientific data.

Recipe score model remains `first-pour-0.3.1`, unchanged. No chemical or sensory
coefficients, real-brew calculations, supplied research evidence or source claims
change. Actual-brew collection and scientific exports remain separate.

## Compatibility and data

Keep key `c6s.first-pour.v03` and version 1 record envelope so v0.3 entries load
without migration. A newly saved experimental B may add optional `baselineId`.
Self-references and malformed IDs are rejected. Repeated saving updates the same
record ID. The original A recipe is copied, never edited by the B flow.

Deleting A does not cascade to B; B remains readable/exportable with an explicit
missing-baseline message. Corrupt stores remain protected; quota failures preserve
old records and permit draft export/retry. No extra preference store is required.
Old counter, legacy journal, IndexedDB bean/photo and actual-brew stores are
untouched. Stored entries persist; an in-progress recipe/experiment/draft remains
in memory and resets on reload. JSON export is a backup; UI import/sync is not
part of this release.

## Validation

- `npm test`: 68 checks including change classification, linked/legacy memory
  round trips, missing baseline, no fabricated radar zeros/edges, context
  separation, escaping and Vietnamese/literal search.
- `npm run build:pages` and `npm run build`: standalone Pages and Vite artifacts.
- `scripts/smoke-discovery.mjs`: 320/390/820/1440 px, existing v0.3 fixtures,
  accent/process/no-match search, unchanged-value rejection, field locking,
  switch/reset, language preservation, full B pour, partial/full radar, distinct
  context warning, linked idempotent save, export contents, reload, free rebrew,
  and deletion of A while retaining B.
- Existing `smoke-first-pour.mjs`: complete free-brew/memory lifecycle, quota and
  corrupt-data recovery. `smoke-pour-layout.mjs`: stable positions/scroll/focus
  and node identity across stages in all four viewports and both VI/EN.
- Existing water/drop/release/final-wait/reduced-motion, live counter, actual-brew
  provenance/calculation/recovery and music lifecycle browser regressions.

Screenshots in `docs/review/v0.4/` use synthetic test data. Browser checks use
Chromium; actual iPad/Safari hardware, human engagement and retention remain
unverified. One-variable game recipe comparisons are not causal real-world
experiments. Expert calibration and a calibrated flavor simulator remain future
work, along with account sync/import, favorites and longer-term GDD systems.
